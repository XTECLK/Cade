Set up
Command guide

Every command, and where it works.

/cade … commands work at the top of a channel. @Cade … commands are messages, so they also work in threads, where most of the work happens. Cade works in three layers, each built on the one before: commands, which always work; the proactive agent, which reads messages in the threads Cade manages and offers what you're about to do; and AI suggestions, which let it read them with AI. Turn the last two on or off in cade.config.json, for every group or for each group on its own.

Start

Tasks and incidents

/cade task

Dev channelTop level

A form for the title, priority and an optional due date. The task is posted in the dev channel. With activeTasksPinning on in cade.config.json, it also stays pinned until it's done.

Example: “Upgrade Node to 22 on staging”, Medium.

/cade incident

Dev channelTop level

Asks only what the incident is. Incidents are always Urgent and due Immediate, and their cards say Incident, so they stand out among the channel's tasks. They're listed first in /cade tasks, summaries and briefs.

Example: “Card payments failing at checkout for EU customers”.

@Cade task @Cade incident

Dev channelIn a message's thread

Starts a task or an incident from a message already in the channel. Cade privately offers a button that opens the form, named from the message's first line; once it's posted, the message moves into its thread.

Example: reply @Cade incident under “Checkout is failing for EU customers”.

Message shortcuts

AnywhereAny message

On any message, in any channel or DM: ⋯ → More actions.

  • New task and New incident open their form, named from the message's first line.
  • Move to existing opens a form to pick an open task or incident.
  • In a dev channel, or when there's only one group, the forms are for that project. Otherwise they ask for the Project first, and Move to existing then lists that project's open tasks.
  • The message is copied into the task's thread, credited to whoever wrote it, so everyone on the task can read it, even if they can't see where it was written. The link back to it, and Cade's note and 📤 under it, work only where they can.
In a task thread

People, status, PRs and releases

These work in a task's thread in the dev channel. Each command takes everything it needs in one go; without it, Cade says what to send. The ⋯ menu on a task's card has Edit, one form with everything: owners, reviewers, testers, status, priority, due date and pull requests (an incident's priority and due date never change, so its form leaves them out); Release, while it has PRs not sent yet, the same form as @Cade release; Export thread, in a project with a Google Doc, which writes the thread as plain text, names included, in a tab of its own under the Doc's Export tab (choosing it again writes the same tab over), to give to whatever summarizes it, and tells only you where; and Archive, as @Cade archive. Save the form, and Cade notes who changed what in the thread, as one message, then asks the people it names to do their part: see who hears what. Sending PRs for approval is @Cade release.

@Cade assign owner @person

Dev channel

Adds people to a role: owner, whoever does the work, whatever it is (dev and developer work too), reviewer (or review) or tester (or test, qa), several at once if you like. Cade notes who assigned whom, and on the next line asks them to start (see notifications). To change several roles at once, use the card's ⋯ → Edit.

  • Reviewers can be added before there's a PR. They're asked to review once one is linked.
Example: @Cade assign qa @Tom

@Cade unassign owner @person

Dev channel

Removes people from a role. Cade notes who removed whom, and on the next line tells them there's no need to do it anymore (see notifications). @Cade unassign @person removes them from every role. The same short words work.

@Cade status in review

Dev channel

Cade sets the status and reacts ✅. Statuses are to do, in progress, in review, in testing, client review and done, typed however you like (IN_PROGRESS, in-progress).

  • With activeTasksPinning on, Done unpins the task; moving it out of Done pins it again.
  • Client review shows whoever set it a private Ask for approval button (set it again to get it back): pick who approves, the client or whoever handles them. Cade asks them in the task's thread to Approve (the task goes to Done) or Not approve (back to In progress). Only they can click.

@Cade pr add <link> @Cade pr remove <link>

Dev channel

Links or unlinks pull requests, one or several. GitHub, GitLab and Bitbucket links are recognised, and shown on the card as repo#number. Linking asks its reviewers to review it; with no reviewer yet, Cade asks who should review, with a people picker.

Example: @Cade pr add https://github.com/acme/booking-web/pull/131

@Cade release @Cade deliver

Dev channel

Sends some of the task's PRs to the client before the whole task is done. A private Choose PRs button opens a form that lists the ones not sent yet and asks what they complete and who approves them. The approver gets them in the task's thread with Approve and Not approve, which only they can click. PRs that weren't approved can be sent again. The task's status doesn't change.

  • The task thread hears the decision, mentioning the owners.
Example: send PR #128 as “Deposit checkout flow (20% default)”.
Priority & due date

Set in the task's thread

Incidents are always Urgent and due Immediate, so theirs never change.

@Cade priority high

Task thread

One of urgent, high, medium or low. Cade sets it and reacts ✅. The card's colour strip follows the priority.

@Cade due 31/12/2026

Task thread

A date as DD/MM/YYYY (also with . or -, or as YYYY-MM-DD), or none to clear it. Cade sets it and reacts ✅.

Move & archive

Keep every channel tidy

Post a new message

Dev channelTop levelAlways on

A message posted on its own in the dev channel, not in a thread, gets a private question to whoever wrote it, so it lands in the right thread: New task, New incident, Move to existing (when something's open) or Not now, the same as the message shortcuts, with the same forms. Starting something from it names it from the message's first line and moves the message into the new thread. This works even with the proactive agent off.

@Cade move <link>

Dev channelIn a message's thread

Moves a message into the task's thread that the link points to. The link is required: without it Cade says so. To pick from the open tasks instead, use the message's ⋯ → Move to existing.

  • Without typing, from anywhere: on the message itself, ⋯ → More actions → Move to existing opens a form with the channel's open tasks and incidents, and nothing is posted until it moves. Outside a dev channel, with more than one group, it asks for the project first. See message shortcuts.
  • With an emoji, in one click: add 🎫 :ticket: to a message in the dev channel to track it, or 🔀 :twisted_rightwards_arrows: to move it. Cade answers only you: a New task button, or the move picker. Add them to Slack's one-click reactions (Preferences → Messages & media) and they sit in the bar you see when hovering over a message. Choose other emoji with reactions in cade.config.json.
  • With a link: paste the link to a task's or incident's message (Copy link on it, or on any reply in its thread) and Cade moves the message there straight away, with a ✅ on your command. Handy for bringing old threads in from before Cade, one after another: start with the oldest, so they land in order.
  • Slack can't move messages, so Cade copies it into the thread, quoted and credited to its author with a link back, replies under the original asking people to carry on there, and marks it with 📤 so it can be skipped.
  • Only the message is copied, not its replies or attachments, and a message in the dev channel is never moved twice.
  • If the original was pinned, it's unpinned: its new thread is where it's followed now.

@Cade archive

Task thread

Puts away a task that's no longer needed: Cade stops tracking it, so it leaves your lists, standups and briefs, and moves to the summary's Archived section, but nothing is deleted. Its card stays, unpinned, saying who archived it, its thread hears who did, and its Sheet row says Archived. The card's ⋯ → Archive does the same. To delete a task, see /cade remove.

Your work

Lists and standups, only for you

/cade tasks

Any channelOnly you see it

Your open tasks, grouped by what you do on each (owned, reviewing, testing), incidents first, then by priority and due date. In a group's dev channel it shows that group; elsewhere, every group. Add any of:

  • development, review or testing: one role only
  • @person: their tasks instead of yours
  • -all: everyone's tasks, by status · -unassigned: tasks with no owner
  • -status=in-progress: one or more statuses, with commas (Done too, if named)
  • -due=@today, -due<@tomorrow, -due>=31/10/2026, -due=none: by due date
Example: /cade tasks review @Mia -status=in-review

/cade standup /cade standup -unassigned

Dev channelOnly you see it

Walks through the open tasks one owner at a time: you first, then everyone else, then the tasks with no owner. Each task has a status menu, and unassigned ones an owner picker; changes are posted in each task's thread. -unassigned goes through just the tasks with no developer. Built to share your screen in a standup.

/cade home

Dev channel

Adds a link to Cade's Home tab (all tasks, my tasks) to the channel's topic, after the topic that's there. Running it again swaps the link, so it appears once. It needs no new permissions.

The Home tab

Cade's app pageOnly you see it

Open Cade under Apps in Slack and its Home tab shows your open tasks, redrawn each time you open it or press Refresh. My Tasks groups yours by what you do on each: to work on, to review and to test, with the ones waiting on you first and an overdue count. Unassigned lists tasks with no one on them, each with Assign to me. All Tasks lists every open task, most urgent first. A project picker narrows it to one group, and Cade remembers your choice and tab. Closed and older tasks are in the group's Google Sheet, linked from the lists. Needs the app updated with npm run slack:update.

The summary canvas

Dev channelOff by default

With summaryCanvas on in cade.config.json (for every group or one), every dev channel's canvas holds a table of its tasks, made with the first new task (taking over the canvas the channel has, if any) and kept up to date as things change: an Open section by priority, then due date, incidents first, then a Closed section of the last 50 done and an Archived section of the last 50 archived, most recent first, each with its title, status, priority, due date, owner, reviewer and tester. With a Google Sheet linked to the group, the canvas also links to it, for every task. Each title opens its thread. The table replaces what the canvas held, and the canvas is made read-only for the channel, since Cade rewrites it on every change; where Slack doesn't allow that, such as on a free plan, it stays editable, and edits are overwritten.

/cade brief /cade brief <group>

Any channelOnly you see itNeeds the group's Google Doc

Writes an executive summary with you, one step at a time, and adds it to the group's Google Doc (its doc in cade.config.json), at the top of its Summary tab, as a section headed with the day it was written. Nothing is posted in Slack. Without a linked doc it says how to link one. It covers the channel's group, or the only one, or the one named. First pick the period, From and To dates: from the day after the last summary's period (the past week, the first time) to today, unless you change them. Then what was completed from the start of From to the end of To: untick any not to mention as done. Then each open task, incidents first, then by urgency: how it's going (on track, at risk, delayed or blocked), its progress such as 3/5, and any notes. Peek at threads shows the latest messages of its thread, to help you write them. Health, progress and notes start as the last summary had them, to add to or change, and what the last summary said is shown above them, to compare. Last, the summary as it will read, with Add to the Google Doc. In the doc each title links to its thread, and notes are bullets under it. Back keeps your answers; nothing about the work itself changes.

/cade debrief /cade debrief <group>

Any channelOnly you see itNeeds the group's Google Doc

After going through the last executive summary with the client, reads its section of the doc back and compares it with what Cade wrote. A bullet of its own with no link is a new task, with the lines under it as its details; lines added under a task are points for its thread. They're suggested one at a time, to Apply or Discard. Apply on a point opens a text box with it, to edit, then posts it in the thread its title links to. Apply on a new task opens the task form, named from it, with an Initial message posted in the task's thread once it's tracked. Each is suggested once: /cade debrief again goes on with the rest, and finds anything added since.

/cade help

Anywhere

Lists everything Cade can do, only to you. A bare @Cade or an unknown @Cade command just points to it.

Proactive agent

Plain words Cade picks up in its threads

With the proactive agent on, Cade reads messages in the task and incident threads it manages, and offers, privately, to act on them. Nothing changes until you click.

On by default. Set "taskStatusChangeDetection": false in cade.config.json, for every group or on one group in channels, for commands only: Cade then reads nothing from messages in threads. Commands, the task card's ⋯ menu, message shortcuts, emoji, and the question about a new message posted in a channel all keep working. You can also keep only some kinds: pr-links, hand-offs, started, progress.

Hand a task to someone

Task thread

Mention someone with what you'd like them to do:

  • Owner: “start working”, “work on”, “look into”, “pick this up”, “take this”, “take care of”, “handle this”, “fix this”, “assign this to”, “over to you”, “implement”
  • Reviewer: “review” · Tester: “test”, “QA”, “verify”
  • Cade suggests adding whoever that part of the message names. Someone only cc'd isn't added. Your own part is yours: “@udara can you implement this while I test it” suggests Udara as owner and you as tester.
Example: “@Rex please start working on this, first cut by Friday?”

Paste a pull request

Task thread

Cade privately offers to link it, in the same summary as any other change it read (PRs: …), with Accept, Edit… and Reject. People your message mentions who aren't reviewers yet are added as reviewers, and the task moves to In review.

Example: “First pass is up: https://github.com/acme/booking-web/pull/128. @Mia can you review this?”

Say how it's going

Task thread
  • Started: “on it”, “started on this” from someone on the task offers In progress.
  • Progress: “lgtm” from a reviewer, “QA passed” from a tester, or “done” from anyone on it offers the next status.
  • Role and status suggestions come together as one private message: a summary of what Cade read, with Accept, Edit… (the task's Edit form, filled in with it) and Reject. The same as AI suggestions, read by phrases instead.
Example: “lgtm, approved the PR”
AI suggestions

One message, every change, read with AI

With AI suggestions on, the proactive agent reads messages in task threads with a small model on Cloudflare Workers AI, not by fixed phrases. That catches more ways of saying things, and several changes in one message.

Off by default. Turn it on with "aiSuggestions": true in cade.config.json, or name another Workers AI model, for every group or only some: { "name": "acme", …, "ai": true } in channels. It needs the proactive agent on: with "taskStatusChangeDetection": false, AI is never asked.

What it reads

Task thread
  • People: owners, reviewers and testers added or removed, several roles in one message. Only people the message mentions, or whoever wrote it, can be added. A mention that only informs (“cc @rex”, “thanks @mia”) changes nothing.
  • Status: when the message says the work moved on, never for a question or a plan.
  • Priority and due date: “this is urgent”, “need it by Friday”, but not an incident's.
Example: “@Rex can you take this over from @Bob? @Mia please review. Need it by Friday, it's blocking the release”

Accept, edit, or reject

Only you see it

Whoever wrote the message gets a private summary of what Cade read, such as Owners: @Rex (Add) · @Bob (Remove) · Reviewers: @Mia (Add) · Priority: High → Urgent · Due: none → 31/10.

  • Accept applies it all, and the thread hears it as one message.
  • Edit… opens the same form as the task card's ⋯ → Edit, filled in with it: every role's people, the status, priority, due date and PRs. Correct anything, then Save.
  • Reject drops it.

Falls back on its own

Always

If the model fails, or takes more than 8 seconds, the message is read by its phrases instead, as with AI off. Pasted PR links and new messages in the dev channel are always read without AI.

Admin commands

For tidying up

Rarely needed, from anywhere, with Copy link on the message. Only you see the answer.

/cade remove <link>

Anywhere, with a linkOnly you see it

Deletes what the link points at, asking first, with a prominent Cancel and a plain Delete that asks again. A task's link deletes its card and Cade's replies in its thread, archived tasks too; a reply's link deletes the reply; any other message's link deletes Cade's replies in its thread, and the message too if Cade posted it. Slack only lets Cade remove its own messages, so people's replies stay under Slack's “This message was deleted”.

/cade replace <link> "New wording"

Anywhere, with a linkOnly you see it

Changes what one of Cade's messages says, such as a reply in a task's thread, in quotes or not. Slack formatting, mentions and links work as in any message, and an edited message notifies no one. A task's card is drawn from the task, so change it with its ⋯ → Edit instead.

/cade retry <link>

AdminAnywhere, with a linkOnly you see it

Runs the suggestions again for a message in a task's thread, with the link from Copy link on it, as if it had just been posted: for one Cade missed, or whose private question was dismissed. Whoever wrote the message is asked again, privately, if there is anything to suggest. Nothing changes until they answer.

/cade export <link>

Anywhere, with a linkOnly you see it

Writes a task's thread as plain text in the project's Google Doc, as the card's ⋯ → Export thread does: in a tab of its own, called the task's title and “(thread)”, under the Doc's Export tab. Each message has its author's name and time, links keep their addresses and files their links. Several links work too, and sending it again writes the same tab over. Nothing is posted, so no one is notified; the reply says where it went. Needs the project to have a Google Doc. It also happens by itself when a task is done (turn that off with exportOnDone in cade.config.json), quietly; the done task's card then links it as Thread export here, after Extra notes here.

/cade resync <link> /cade resync summary /cade resync sheet

Anywhere, with a linkDev channelOnly you see it

With a task's link (several work too), redraws its card from what Cade has stored, and sends it to the Sheet and summary again, quietly. In a project with a Google Doc, it also makes the task's notes page if it has none, as tasks made before pages existed have: an empty tab of its own under the Doc's Notes tab, for notes you write by hand. The card then links it as Extra notes here. New tasks get theirs as they are created. /cade resync summary, in a dev channel, rewrites its summary canvas in full, with its title, and makes it read-only again. /cade resync sheet, in a dev channel, sends all of its tasks to the group's Sheet: the first fill when the Sheet is added later. After that every change reaches it by itself, and it is safe to run again. Nothing is posted, so no one is notified.

Set it up

Up and running in minutes, with an AI agent guiding you.

Claude Code is the easiest, and any coding agent that can run terminal commands works too. It runs every command, checks it worked, and stops whenever it needs you. Your tokens never leave your terminal.

  1. 1

    Copy it to your repo

    Fork Cade on GitHub and clone your copy.

  2. 2

    Start the agent

    npm run setup with Claude Code, or paste the setup prompt into another agent.

  3. 3

    Follow along

    Click through the logins and Slack settings when it asks. That's it.
