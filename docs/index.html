    How it works

    One thread per task, from first message to done.

    Requests arrive anywhere. Your team works in its dev channel. Cade brings each one in and keeps it moving.

    1. 1

      Someone asks

      On any message, in a client's channel or a DM: ⋯ → New task, pick the project, and the message is copied into the new task's thread.

    2. 2

    3. 3

      Build & review

    Features

    Everything a project needs, in the channels you already use.

    From anywhere

    • New task, New incident or Move to existing on any message, in any channel or DM
    • Pick the project; the message is copied into the task's thread
    • Works even where not everyone can see the original

    Dev channel

    • Tasks with owners, reviewers and testers, for any kind of work
    • Statuses: To do, In progress, In review, In testing, Client review, Done
    • Live status card (optionally pinned until done), with a ⋯ menu to edit or archive

    Talk naturally

    Write "@mia can you review this" or paste a PR link in a task's thread. The proactive agent offers, privately, to assign or link it, optionally with AI, and changes nothing without a click.

    Incidents

    /cade incident posts an urgent incident and tracks it in the dev channel immediately, marked as an incident. No triage step.

    Partial releases & client review

    Send finished PRs to the client before the whole task is done. Whoever you pick approves or pushes back in the task's thread.

    Tidy channels

    Stray messages are moved into the right thread with a link back, and marked 📤 so everyone can skip them.

    Your tasks

    /cade tasks lists your work by role, with filters for people, status and due dates. Only you see it.

    Standup

    /cade standup walks the team's open tasks one owner at a time. Update statuses and assign as you go.

    Google Sheet

    Every task, status, person and date is recorded in a Sheet automatically, ready for reporting and billing.

    Three layers

    Commands always work. Cade can also read along, with or without AI.

    Each layer builds on the one before. Turn the proactive agent and AI on or off in cade.config.json, for every group or one group at a time, and Cade still asks before it changes anything.

    1 · Commands

    Always on

    You say exactly what to do, and Cade does it.

    • /cade … and @Cade … commands
    • The ⋯ menu on task cards (Edit, Release, Export thread, Archive), message shortcuts and emoji
    • A message posted on its own in the dev channel gets a private question: track it as a task or incident, or move it to an existing thread

    2 · Proactive agent

    suggestions · on by default

    Cade reads messages in the threads it manages and offers, privately, what you're about to do.

    • “@mia can you review this?” offers to add a reviewer
    • A pasted PR link offers to link it
    • “on it”, “lgtm”, “done” offer the next status
    • Off means commands only: nothing is read from messages in threads

    3 · AI suggestions

    ai · off by default

    The proactive agent reads task threads with a small model on Cloudflare Workers AI, so one message can mean several changes.

    • Several people across roles, added or removed
    • Status, priority and due date (“need it by Friday”)
    • A summary to Accept, Edit… in the task's form, or Reject
    • Needs the proactive agent on, and falls back to phrases if the model fails

    Principles

    Simple on purpose.

    Nobody leaves Slack

    Clients, developers and QA all work in threads they already read. No new tool to log in to.

    Clear ownership

    The team owns its tasks. The client approves only what they're asked to, and incidents stay urgent.

    Cade only asks

    Suggestions are private and change nothing until someone clicks. Deletes ask twice.

    One source of truth

    Task cards, summaries and the Sheet are rendered from the same record, so they never disagree.

    Set it up

    Up and running in minutes, with an AI agent guiding you.

    Claude Code is the easiest, and any coding agent that can run terminal commands works too. It runs every command, checks it worked, and stops whenever it needs you. Your tokens never leave your terminal.

    1. 1

      Copy it to your repo

      Fork Cade on GitHub and clone your copy.

    2. 2

      Start the agent

      npm run setup with Claude Code, or paste the setup prompt into another agent.

    3. 3

      Follow along

      Click through the logins and Slack settings when it asks. That's it.
