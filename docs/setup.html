Set up

Set up Cade in minutes. One command guides you.

You get one Cloudflare Worker and one Slack app. There's no server to run. One command, npm run setup, does the setup with you: it runs each step, checks it worked, and stops whenever it needs you to click something.

  1. 1

    Copy the deploy template to your own repo

    On the cade-deploy page, click Use this template and make the copy private. It holds your settings, and the setup asks which version of Cade to deploy: a release, or the latest. Then clone it:

    git clone https://github.com/<you>/<your copy>.git cade-deploy
cd cade-deploy
  2. 2

    Run the setup

    In your cade-deploy folder run:

    npm run setup

    It skips what's already done, so if you stop, run it again to carry on.

  3. 3

    Follow along

    Each step says what it's doing. It stops and tells you exactly what to do when a step needs a person:

    • Logging in to Cloudflare in your browser
    • Making a Slack app configuration token, and installing the app
    • Giving the first admin's Slack member ID. Then, in Slack, you create a channel, invite Cade, and click Add project on its Home tab
    • Optionally, making a GitHub token, so task cards show which pull requests are merged
  4. 4

    Try it

    Send /cade task in your dev channel to track a task, or, on any message anywhere, choose ⋯ → More actions → New task. Send /cade help for the short list, or see the demo and every command.

What you need

  • Node.js 22.18 or newer, and git
  • A Cloudflare account (the free plan is enough)
  • A Slack workspace where you can create apps

Your tokens stay with you

The commands that need a token or secret ask for it themselves, hidden, in your own terminal. None is ever written to a file or a commit.

Optional

Pull requests open, merged or closed

With a GitHub token, Cade reads every 15 minutes whether each GitHub pull request linked to an open task is open, merged or closed, and the task's card counts them: Pull requests: 2 open · 1 merged. Without one, every pull request counts as open. It's the last, optional step of the setup, or, any time, in your deploy repo:

npm run github

It opens GitHub's page for a new classic token with the repo scope ticked, asks for the token, hidden, checks it with GitHub, and stores it in Cloudflare. A classic token reads every organisation your account can, where a fine-grained one reads a single owner's repositories. repo is the only classic scope that reads private repositories' pull requests, though Cade only reads whether each is open, merged or closed. If an organisation uses SAML single sign-on, authorize the token for it: Configure SSO on the token's page. The next run of the cron reads them.
